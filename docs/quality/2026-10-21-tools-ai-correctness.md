## AI: загрузка именно запрошенной страницы

Публичные Context-модели удаляли query до загрузки страницы. Поэтому вход `https://example.com/?p=42` превращался в запрос к главной. Для планировщика перелинковки страницы `?p=42` и `?p=43` ошибочно считались одним источником и отклонялись.

Теперь нормализованный адрес сохраняет query до получения HTML. Fragment исключается из HTTP-адреса загрузки. Проверка публичного URL, принадлежности проекта и ограничений origin сохранена. После загрузки query удаляется из URL полей provider-контекста; в базе сохраняется уже этот разрешённый контекст. Модель не получает исходные параметры URL из этих полей.

Дубликаты полных адресов по-прежнему отклоняются публичными Context-моделями. После редактирования URL provider-модели различают источники по индексам массива, используемым и в output-контрактах. Проверки границ индексов, повторяющихся связей и ссылок страницы на саму себя сохранены. Это позволяет анализировать разные query-страницы, чьи публичные адреса после редактирования совпадают.

Регрессии проверяют правильный HTML вместо содержимого главной, два отдельных query-источника планировщика и отсутствие параметров в сохранённом контексте, получаемом worker. Старые тесты, требовавшие удаления query до fetch, обновлены на проверку обеих границ: полный адрес загрузки и отредактированный адрес provider-контекста. Проверка недопустимых URL и точных дубликатов не ослаблена.

## AI: непригодные входы до платной обработки

При пустом списке замечаний невозможно сформировать допустимый action plan: контракт требует хотя бы одно действие с существующим `issue_id`. Раньше такой запрос ставился в очередь и мог расходовать работу провайдера, хотя любой ответ отклонялся бы.

Теперь API возвращает `422 ai_source_no_issues` до создания run и резервирования кредитов. RU/EN интерфейс объясняет, что замечаний для плана нет и кредиты не списаны. Сервисный тест проверяет неизменный баланс, нулевой резерв, пустой список задач и отсутствие задачи для worker. Браузерные сценарии проверяют сообщение в обоих языках и отсутствие внутренних сообщений backend в интерфейсе.

Длинные title/H1 также приводили к `ai_source_unavailable`: HTML доступен, но скопированное значение превышало предел provider-схемы. Snapshot теперь ограничивает title до 300 и H1 до 500 символов с явным маркером `… [truncated]`. Тем же способом обозначается усечение текста при существующем лимите в 20 000 символов. Контракт не расширен неограниченными строками. Проверены search intent, competitor gap и internal linking.

Для частотных фраз раньше сначала удалялись стоп-слова. Это создавало отсутствующее в исходнике сочетание `audit teams` из `audit for teams`. Фразы также перескакивали через границы предложений и блоков. Теперь n-граммы строятся из соседних слов внутри одного предложения и HTML-блока. `<hr>` завершает текстовый блок без изменения глубины вложенности; `<br>` остаётся пробелом внутри блока. Удаление стоп-слов сохранено для списка отдельных значимых слов, где оно не меняет соседство.

## Canonical

- Повреждённые IPv6/port значения и неподходящие схемы из HTML дают диагностический результат вместо необработанного исключения. Слишком длинный canonical также остаётся ограниченным ответом с сообщением о недопустимом адресе.
- `/page` и `/page/` больше не считаются автоматически одним ресурсом. Нормализация регистра хоста и стандартного порта сохранена; query остаётся значимым для сравнения.
- `noindex` учитывается и из `X-Robots-Tag`, включая директиву `none` с префиксом робота.
- Интерфейс не показывает зелёный успешный canonical для HTTP 503 и не превращает неопределённое совпадение в подтверждённое.
- Рекомендации отдельного canonical-инструмента переводятся на русский через общий словарь. Английский интерфейс сохраняет исходный текст. Некорректный canonical проверяется в браузере для RU/EN.
