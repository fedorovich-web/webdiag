## Полный аудит сайта

Кабинет проекта теперь получает существующий полный контракт `/site-audits`, а не урезанный `/crawls`. Отчёт показывает оценки страниц, количества и приоритеты замечаний, затронутые URL, рекомендации и историю. Переход к сохранённому одиночному аудиту обозначен как отчёт страницы.

Исправлены причины недостоверных результатов обхода:

- Конечный URL редиректа учитывается один раз. Если ссылка ведёт на alias, конечная страница считается обнаруженной; sitemap-only URL при этом не становится обнаруженным без внутренней ссылки.
- URL с query явно исключаются и учитываются отдельным счётчиком. Раньше удаление query могло приводить к загрузке другой страницы. Параметры не сохраняются; зависимые от них страницы не анализируются.
- Ограничения числа страниц, ссылок и времени обозначают неполный обход. Истечение времени до первой HTML-страницы возвращает `crawl_deadline_exceeded` вместо пустого успешного результата.
- Ошибка объявленного sitemap не скрывается успешным резервным запросом. Некорректные адреса в sitemap не обрушивают задачу.
- При неполном графе, ошибках HTTP, недоступных страницах или неполном sitemap вывод о страницах без внутренних ссылок подавляется. UI показывает «Не оценено» и причину частичного результата. Страница с HTTP 503 сохраняет фактический статус и замечания.
- Относительные ссылки учитывают первый активный `<base href>`. В русской сводке переведены критичность, замечания и рекомендации; обычные замечания используют общий словарь, шесть типов замечаний всего сайта имеют отдельные записи. Английский ответ и сохранённые данные не меняются.

Обход ограничен общедоступными HTML-страницами одного origin, JavaScript не выполняется. Даже завершённая задача не подтверждает обнаружение всех страниц сайта. Новая сводка сообщает эти границы; фиксированное обещание 25 страниц убрано, показывается фактический лимит результата.

## Метаданные, ссылки и изображения

Общие функции разрешения HTML-адресов используются для canonical, ресурсов, ссылок и обхода. Повреждённые, неподходящие и слишком длинные URL дают диагностический результат и не отправляются в запрос как усечённые адреса. Проверка публичных адресов и SSRF остаётся обязанностью `SafeHttpFetcher`.

Длинные title, описания, атрибуты изображений и favicon ограничены в ответе с маркером усечения; измеренные длины title и description берутся из оригинала. Ресурсы из вложенных template не учитываются. Из `srcset` извлекаются кандидаты URL с сохранением допустимых запятых внутри адресов; data URL не отправляются в HTTP-загрузку. Это извлечение URL, а не полный браузерный выбор изображения или валидатор дескрипторов.

Правила для base URL и разбора кандидатов сверялись с [HTML Standard: document base URLs](https://html.spec.whatwg.org/multipage/urls-and-fetching.html#document-base-urls) и [HTML Standard: parsing a srcset attribute](https://html.spec.whatwg.org/multipage/images.html#parsing-a-srcset-attribute).

HTML-инструменты отклоняют не-HTML источник. HTTP-ошибки источника не превращаются в успешную проверку. MIME изображения проверяется по основному Content-Type; расширение имени и параметры заголовка не подменяют MIME. HTML-ответ 200 на `/favicon.ico` не считается найденной иконкой. Ошибка загрузки или не-изображение не получает положительный признак современного формата и не улучшает агрегат. Неположительные и нечисловые width/height не подтверждают резервирование места.
