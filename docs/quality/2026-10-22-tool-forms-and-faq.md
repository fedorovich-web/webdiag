## Основания для формулировок

Страницы конкурентов использованы для выбора практических тем: подготовка ввода, чтение результата, причины отсутствия данных, исправления и повторная проверка. Ответы написаны для реализованных возможностей WebDiag. Наличие у конкурента массовой обработки, определённого формата или способа проверки не считается доказательством такой возможности у WebDiag.

В частности: дубли группируются по Title и Description, без обещания анализа H1; генератор favicon создаёт PNG 32, 48, 180, 192 и 512 px; CORS проверяет обычный запрос без OPTIONS; карта редиректов сравнивает первый переход; публичный разбор sitemap не равен обходу карт в аудите проекта. Для инструментов без точного аналога вопросы сформулированы по действиям доступной формы, ответы — по её реализации.

Исправлены противоречивые описания: аудит проекта по умолчанию ограничен 100 страницами и умеет читать списки дочерних карт в пределах лимитов; аудит страницы содержит 22 группы проверок и доступные измерения PageSpeed. Убрано обещание ускорения индексации в 2–4 раза: [документация Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview) не гарантирует обход и индексацию адресов из sitemap.

## Обработка данных

В общей подписи страницы отсутствовал класс `dns_tls`, из-за чего DNS/TLS ошибочно назывались локальными инструментами. Все исполнители, кроме `browser`, теперь получают пояснение о серверных запросах. Для двух браузерных форм, использующих серверный конвертер AVIF, отдельно указано: JPEG/PNG/WebP обрабатываются в браузере, AVIF передаётся конвертеру WebDiag. Компонент страницы передаёт slug для выбора соответствующего пояснения. Регрессии обеих ошибок воспроизведены до исправления.
